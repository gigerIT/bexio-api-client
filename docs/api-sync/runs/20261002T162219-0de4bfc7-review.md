## Verified documentation discrepancies

- Milestone edit is documented as POST; an existing disposable milestone returned
  404 for POST and 200 for PATCH. The client uses PATCH and the README shows the
  discrepancy.
- Contact-relation search's published response repeats the Contact schema. Live
  search returns relations, so the relation DTO is retained.
- Outgoing-payment list `data` is documented as an object; live bill-scoped lists
  return an array. Manual outgoing payments cannot be updated; IBAN and QR can.
- V4 banking updates require `type`, although the published update schema omits
  it. Fetched amounts may be strings, but writes require JSON numbers. QR writes
  reject `allowance`; IBAN payments do not retain QR additional information.
- Invoice position widgets reject `is_optional`; updates reject hierarchy fields.
  Existing article create/update and document-shell rules remain intact.
- Existing task string-boolean, item `article_type_id`, sales validity-date and
  automatic document-number caveats are preserved with live evidence.

Schema review included nested DTOs, typed collections, enums, nullable fields,
request/response splits, list envelopes and route context. Numeric identifiers
and byte counts remain integers where the documentation loosely says `number`.
Unused/internal schema aliases and **197 empty path stubs** do not establish new
public APIs. Legacy wrappers are retained when deprecation or an omitted public
operation does not prove removal.
